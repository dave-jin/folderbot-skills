# Project Charter — 목적·역할·위임 레벨 세 가지만 못 박는다

프로젝트가 흔들리는 이유는 정보가 부족해서가 아니다. **무엇이 끝인지**, **여기서 내가 무엇을 하는 사람인지**, **에이전트에게 어디까지 맡길지**가 적혀 있지 않아서다. 이 세 가지가 폴더 안에 문장으로 있으면 이후에 만드는 파일·산출물·todo 를 매번 그 문장에 비춰 볼 수 있고, 에이전트도 폴더마다 다르게 굴지 않는다. 이 스킬이 내놓는 것은 그 판단 기준 한 장이다.

이 스킬은 **카파시의 순서**를 따른다. ① 관련 맥락을 **먼저 전부** 모은다 → ② 결과물이 아니라 **선택지와 장단점**을 들고 간다 → ③ 고르는 것은 사용자다 → ④ 쓴 뒤에 사용자가 검토한다. 즉 이 스킬 자체가 위임 Level 2~3 으로 돈다.

**⛔ 여기서 프로젝트 계획서를 쓰지 않는다.** 길게 쓰면 아무도 안 읽고, 안 읽는 기준은 기준이 아니다. 새로 쓰는 목적·역할 블록은 **30줄 이내**로 유지한다.

## 1단계 — 대상 폴더 확정

- 인자로 폴더가 오면 그 폴더, 아니면 현재 작업 폴더를 쓴다. 볼트 루트에서 불렸다면 `2. Projects` 목록을 보여 주고 하나를 고르게 한다.
- 여러 폴더를 요청받아도 **한 번에 한 폴더씩** 끝낸다. 목적과 역할은 폴더마다 다르고, 몰아서 물으면 답이 뭉개진다.
- 파일명은 **대문자 `CLAUDE.md`** 다. 같은 폴더의 `AGENTS.md` 는 「정본은 CLAUDE.md 다」라는 **평문 한 줄**로만 둔다(⛔ `@import` 금지 — Codex·Cursor 는 따라가지 못한다). 기존 `AGENTS.md` 에 본문이 있으면 `CLAUDE.md` 로 옮긴 뒤 한 줄로 바꾼다.

## 2단계 — 맥락을 전부 모은 뒤 초안을 만든다 (백지 질문 금지)

질문하기 전에 근거부터 모은다. 사용자에게 아무것도 없이 "목적이 뭔가요"라고 묻는 것은 시간을 뺏는 일이다. 초안을 놓고 고치게 하면 3분이면 끝난다. **카파시의 1단계, 곧 맥락을 먼저 전부 넘기는 일을 여기서 한다.** 폴더가 비어 있을수록 밖에서 더 모아야 한다.

**폴더 안** — 폴더명(날짜는 데드라인, 타입 접두어는 역할의 힌트) · `readme.md` Overview · `todo.md` 미완료 항목 · 기존 `CLAUDE.md` · `state.md`(있으면 현재 상태) · 하위 폴더 구조. 볼트 탐색에는 `vault_search`·`vault_tree` 를 `Glob`/`Grep` 보다 먼저 쓴다. 이 도구가 없는 환경이면 `Glob`/`Grep` 으로 한다.

**폴더 밖** — ① 같은 주제를 다룬 **다른 프로젝트·Area 폴더**(`vault_search`) ② **연결된 노트 앱**이 있으면 그 프로젝트의 노트 ③ 외부 사실이 걸리면 **웹 검색**(제품·가격·회사처럼 변하는 사실은 지어내지 않고 검색한다) ④ 필요하면 이 프로젝트와 연결된 메신저 대화방. 연결된 도구가 없으면 폴더 안의 사실만으로 진행한다. 모은 것은 `readme.md` 「📎 자료」에 출처와 함께 적어 두고, 폴더에 없는 파일은 복사하지 말고 링크한다.

여기서 **목적 1문장 + 역할 1문장 + 위임 레벨 초안**을 만들어 둔다. todo 항목들이 실제로 무엇을 향해 굴러가고 있는지가 가장 좋은 단서다. 초안은 하나만 만들지 않는다. **실제로 갈릴 만한 해석 2~3개**를 장단점과 함께 준비한다. 그것이 3단계의 선택지가 된다.

## 3단계 — 질문 (`AskUserQuestion`, 최대 4개)

초안을 **첫 번째 선택지**로 넣고, 나머지는 실제로 갈릴 만한 다른 해석으로 채운다. 사용자는 고르거나 직접 쓴다.

| # | 묻는 것 | 좋은 답의 조건 |
|---|---|---|
| 1 | **끝난 상태** — 무엇이 되어 있으면 이 프로젝트가 끝인가 | 활동이 아니라 **상태**다. 기한이 붙어 있다 |
| 2 | **성공 기준** — 끝났다는 것을 무엇으로 확인하나 | 숫자나 증거 1~3개 (참석 100명 / 계약서 서명 / 원고 전달) |
| 3 | **역할** — 이 안에서 사용자는 무엇을 하는 사람인가 | 직함이 아니라 **판단하고 결정하는 자리** |
| 4 | **위임 레벨** — 이 폴더에서 에이전트에게 어디까지 맡길 것인가 | 기본 레벨(대개 2~3) + Level 4 로 올릴 일 + ⛔ 끝까지 Level 1~2 에 둘 일(발송·결제·삭제·대외 공개) |

답이 두루뭉술하면(`잘 되게 한다`·`강의를 한다`) 한 번 더 좁힌다. 되묻는 말은 하나면 충분하다. 목적이면 **"그게 됐는지 안 됐는지 누가 봐도 알 수 있나요?"**, 역할이면 **"이 일을 왜 남이 아니라 내가 해야 하나요?"**, 위임이면 **"이게 틀렸을 때 되돌릴 수 있나요?"** 라고 묻는다. 되돌릴 수 없으면 Level 3 이상으로 올리지 않는다.

위임 5단계 눈금(마이클 하얏트)은 이렇다. **1** 시키는 대로 · **2** 조사해서 옵션을 갖고 와 · **3** 추천안까지, 최종 승인은 내가 · **4** 결정하고 실행한 뒤 알려줘 · **5** 알아서 해. 역할(3번)이 「남이 대신 못 하는 지점」을 담으므로 「독특함」을 따로 묻지 않는다.

⚠️ 답을 지어내지 않는다. 근거가 없는 칸은 비워 두고 `⚠️ 미확정` 으로 남긴 뒤 나중에 채운다. 틀린 기준은 없는 기준보다 나쁘다.

## 4단계 — CLAUDE.md 쓰기

**새 파일이면** 이 템플릿을 그대로 쓴다.

```markdown
# <폴더명> — 작업 지침

## 🎯 목적
<끝났다고 말할 수 있는 상태 한 문장> — **기한 YYYY-MM-DD**
- 성공 기준: <검증 가능한 증거 1~3개>
- 범위 밖: <이 프로젝트에서 하지 않는 것>

## 🧑 나의 역할
**<한 단어 포지션>** — <남이 대신 못 하는 한 문장>
- 직접 한다: <2~3개>
- 맡기거나 안 한다: <1~2개>

## 🎚 이 폴더에서의 위임 레벨
- 기본: **Level 2~3** — 접근법 2~3개와 장단점을 먼저 갖고 온다. 고르는 것은 사용자다.
- Level 4 로 올린 것: <예: readme 기계 구역 갱신 — 사후 보고만>
- ⛔ 끝까지 Level 1~2 인 것: <예: 발송·결제·삭제·대외 공개>

## 🧭 정렬 규칙
- 새 파일·산출물·todo 는 **목적을 앞당기는지, 역할에 맞는지** 먼저 본다. 어긋나면 만들기 전에 말한다.
- 목적·기한·역할·위임 레벨이 바뀌면 **이 절을 먼저 고친다.** 이 폴더 판단의 상위 기준이다. **레벨을 올리면 날짜와 함께 여기 적는다** — 신뢰가 쌓인 만큼 위임이 올라간 기록이다.
- 이 아래에는 **이 폴더에서만 통하는 사실**만 덧붙인다. 전역·볼트 규칙은 복사해 오지 않는다.

_YYYY-MM-DD 확정_
```

**기존 파일이 있으면 통째로 덮어쓰지 않는다.** 머리말 바로 뒤에 위 네 절(🎯·🧑·🎚·🧭)을 끼워 넣는다. 🎯·🧑·🧭 는 있는데 🎚 만 없으면 🎚 절만 끼워 넣는다. 이미 쌓인 폴더 지식은 그대로 아래에 둔다. 여러 세션에 걸쳐 모인 실측이라 다시 만들 수 없기 때문이다. 30줄 기준은 **새로 넣는 블록**에 적용한다. 기존 본문이 지나치게 길면 줄이자고 제안만 하고, 잘라내는 일은 사용자가 승인한 뒤에 한다.

## 5단계 — 정렬을 점검하고 보고한다

쓰고 나서 그 자리에서 한 번 대조한다. 이 파일이 실제로 일하기 시작하는 지점이 여기다.

- `todo.md` 미완료 항목 가운데 **목적을 앞당기지 않거나 역할 밖**인 것을 골라 이유 한 줄과 함께 보고한다. ⛔ 임의로 지우거나 새 항목을 넣지 않는다. 판단은 사용자가 한다.
- `readme.md` Overview 와 목적 문장이 어긋나면 알린다. Overview 는 사용자가 쓴 문단이고 다른 곳과 동기화될 수도 있으므로 **대신 고치지 말고 수정안만** 제시한다.
- 마지막에 `rondo_open` 으로 만든 파일을 띄운다. "열어 보세요"라고 쓰지 않는다. 이 도구가 없는 환경이면 파일 경로를 알려 준다.

## 판정 예시

| ✗ | ✓ |
|---|---|
| 목적: AI 강의를 잘 진행한다 | 목적: 10월 밋업이 참석 100명·후기 20건으로 끝나 있다 — 기한 2026-10-15 |
| 목적: 책을 쓴다 | 목적: 초고 12장 전량을 출판사에 넘긴 상태 — 기한 2026-11-30 |
| 역할: 강사 | 역할: **커리큘럼 설계자** — 실습 과제와 합격 기준은 나만 정할 수 있고, 촬영과 모객은 주최 측이 한다 |
| 역할: 멘토 | 역할: **의사결정 스파링 상대** — 대표의 결정을 반박하는 자리다. 실행과 문서화는 팀이 한다 |
| 위임: 알아서 잘 해줘 | 위임: 기본 Level 2~3 · **Level 4** = readme 갱신·자료 정리 · **⛔ Level 1~2** = 고객사에 보내는 메일·정산 문의 |
