# 바깥 채널 읽기 절차 — /start 4단계

**연결된 도구가 있으면 — 메일·메신저·노트 앱·캘린더(MCP 커넥터나 CLI) — 거기서 최근 변화를 가져오고, 없으면 폴더 안의 사실만으로 진행한다.** 어느 채널도 필수가 아니다.

각 채널의 **목적은 「조회 창 안에서 이 프로젝트에 무엇이 달라졌나」를 한 줄씩 건지는 것**이다. 원문을 모으는 일이 아니다. 연결된 채널을 한 턴에 동시에 열고, 결과를 아래 표 한 장으로 모은다.

```
| 날짜 | 채널 | 누가 | 무엇이 바뀌었나 | 출처(스레드 제목·대화방·노트 제목) |
```

이 표가 5단계 갱신과 6단계 브리핑의 유일한 입력이다. 표에 없는 사실은 문서에 쓰지 않는다.

---

## 📧 메일

연결된 메일 도구(예: Gmail 같은 메일 서비스의 MCP 커넥터)를 쓴다. 메일 도구가 둘 이상이면 주로 쓰는 쪽을 먼저 쓰고, 안 되면 다른 쪽으로 넘어간다. 모두 안 되면 「메일 측정 실패」.

1. 계정이 둘 이상 연결돼 있으면 **계정마다** 같은 질의를 돌린다. 주 계정만 보고 끝내면 다른 계정으로 온 확정 메일을 놓친다.
2. 3단계에서 뽑은 **상대 이름·기관명·프로그램명**과 조회 창 시작일로 검색한다. 예: `after:YYYY/MM/DD (이름 OR 기관 OR 프로그램)`. 프로젝트 폴더명을 그대로 넣지 않는다. 상대는 그 이름을 모른다.
3. 스레드 제목과 스니펫으로 먼저 거른다. **본문은 요청·확정·변경·마감이 담긴 것만** 연다. 뉴스레터와 자동 알림은 열지 않는다.
4. 상한은 스레드 20개다. 넘치면 최신순으로 자르고 「20개 이상 — 더 있음」이라고 적는다.

**건질 것**: 상대가 준 마감 · 확정된 일정 · 요청받은 산출물 · 받은 첨부 · 내가 아직 답하지 않은 메일(⇒ 「상대가 기다리는 것」).

---

## 💬 메신저

연결된 메신저 도구(예: Slack 같은 업무 메신저의 MCP 커넥터나 로컬 CLI)가 있을 때만 읽는다.

1. 도구가 동기화가 필요한 방식이면 **읽기 전에 먼저 동기화한다.** 동기화가 실패하면 「메신저 측정 실패」로 표에 적고 다음 채널로 간다. 낡은 사본으로 답을 만들지 않는다.
2. 사용자가 **프로젝트와 대화방을 연결한 매핑표**를 두고 있으면 그 표부터 읽고, 이 프로젝트에 붙은 방만 가져온다.
3. 매핑된 방이 없으면 대화방 목록에서 **상대 이름·기관명으로 방을 특정**한다. 여러 개면 최근 메시지가 있는 쪽을 고른다. 찾은 방은 매핑표가 있으면 거기에 등록한다.
4. 방마다 **조회 창 안의 메시지만** 골라 본문을 읽는다. 방 식별자를 이름이 아니라 ID 로 받는 도구라면 ID 를 넣는다. 이름을 넣고 조용히 0건이 나오는 경우가 있다.
5. 상한은 방 3개, 방당 메시지 묶음 15개다. 넘치면 최신순으로 자른다.

**하지 않는 것**: 방을 특정하지 않은 전체 키워드 검색 · 대화 전체 덤프 · 메시지 전송. 첨부가 업무에 필요하면 방을 특정한 상태에서 필요한 만큼만 받는다.

**건질 것**: 결정(날짜·금액·인원) · 요청 · 일정 변경 · 내가 아직 답하지 않은 질문. 개인 연락처와 계좌번호는 표에도 문서에도 옮기지 않는다.

---

## 📝 노트 앱

사용자는 맥 앞이 아닐 때 노트 앱(예: Notion 같은 도구)에서 프로젝트 노트를 고치기도 한다. **그 수정이 readme 에 아직 안 들어와 있을 수 있다.** 이 채널은 「바깥 소식」이 아니라 「사용자가 밖에서 남긴 메모」다.

1. 프로젝트 이름·상대 이름으로 노트를 검색한다. 검색이 시맨틱 방식이라 특정 언어에서만 잘 잡히는 도구라면 **다른 언어나 다른 키워드로 한 번 더** 찾는다.
2. 이 프로젝트에 대응하는 노트를 연다. 여럿이면 **가장 최근에 수정된 것**을 연다.
3. readme Overview 와 다른 문장이 있으면 그것이 사용자의 최신 판단일 가능성이 높다. 표에 「노트 · 사용자 · …」로 적고, 5단계에서 readme 에 **덧붙인다**(덮지 않는다).
4. 노트를 고치거나 옮기지 않는다. 여기서 노트를 쓰면 readme 와 노트가 서로를 덮는다.

없으면 「노트 없음」이라고 적는다. 검색어를 바꿔 두 번 찾은 뒤에만 그렇게 적는다.

---

## 📅 캘린더

1. 연결된 캘린더 도구에 상대 이름·기관명으로 **오늘부터 기한까지**의 일정을 묻는다.
2. 건질 것은 **다음 접점**(미팅·강의·마감) 하나와 그 날짜다. 브리핑의 긴급도가 여기서 나온다.
3. 캘린더의 마감과 폴더명의 `YYYY-MM` 이 다르면 표에 적고 **결정 목록**에 올린다. 폴더명은 바꾸지 않는다.

---

## ✅ 할 일 앱 (선택)

연결된 할 일 앱이 있으면 이 프로젝트 이름이나 태그가 붙은 열린 할 일을 본다. todo.md 와 어긋나면(한쪽에만 있으면) 표에 적는다. 새로 만들지 않는다. 7단계에서 묻기만 한다.

---

## 측정 실패를 적는 법

「없음」과 「못 읽음」은 다르다. 연결은 되어 있는데 못 읽었으면 브리핑 첫 줄 옆에 **`측정 실패: 메신저(동기화 실패 — 로그인 만료)`** 처럼 이유와 함께 적는다. 이것을 빼면 사용자는 「메신저엔 아무 일도 없었구나」로 읽고, 그 사이 상대가 보낸 마감을 놓친다. 애초에 연결되지 않은 채널은 「연결 안 됨」으로 한 번만 적는다.
