# /start — 프로젝트를 다시 손에 잡는다

프로젝트를 여러 개 동시에 굴리다 보면, 한 프로젝트를 2주 만에 열었을 때 **어디까지 했는지, 그 사이 상대가 무엇을 보냈는지, 그래서 지금 무엇을 해야 하는지**가 머릿속에 없다. 폴더의 문서는 마지막으로 닫은 날에 멈춰 있고, 그 뒤의 사실은 메일과 메신저에 흩어져 있다.

이 스킬이 내놓는 것은 두 가지다. ① 폴더 안 문서가 **바깥 사실을 따라잡은 상태**, ② **지금 당장 할 일 하나**가 적힌 브리핑. 목록을 길게 주는 것은 결과물이 아니다. 항목이 많아질수록 아무것도 남지 않는다.

**⛔ 지어내지 않는다.** 이 스킬은 「그럴듯한 현황」이 아니라 「근거 있는 현황」을 만드는 도구다. 모든 사실에는 출처(날짜 + 채널)가 붙고, 못 읽은 채널은 「측정 실패」로 적는다.

## 순서와 이유

```
1 대상 폴더 확정 → 2 관문(목적·역할) → 3 안쪽 읽기 → 4 바깥 읽기(병렬, 선택)
→ 5 한 번에 갱신(readme·todo) → 6 브리핑 → 7 끝내기
```

**바깥을 다 읽은 뒤 한 번에 갱신한다.** 메일을 읽고 고치고, 메신저를 읽고 또 고치면 채널끼리 어긋나는 사실(예: 메일은 9/12, 메신저는 9/15)을 못 잡는다. 모아서 대조한 뒤 쓰면 한 번에 끝나고, 어긋난 것은 `⚠️ 확인 필요` 로 드러난다.

**관문이 먼저다.** 우선순위는 「이 일이 목적을 앞당기는가」로 매기는데, 목적이 적혀 있지 않으면 매길 기준이 없다. 그래서 `CLAUDE.md` 에 목적·역할이 없으면 다른 일을 하기 전에 `/project-charter` 로 그것부터 세운다.

## 1단계 — 대상 폴더 확정

- 인자로 폴더나 프로젝트 이름이 오면 그것을 쓴다. `vault_search` 로 `2. Projects` 안에서 찾고, 둘 이상 맞으면 `AskUserQuestion` 으로 고르게 한다.
- 인자가 없으면 **현재 작업 폴더**를 쓴다. 그 폴더가 `2. Projects/<프로젝트>` 의 하위 폴더면 프로젝트 루트로 올라간다.
- **볼트 루트(오케스트레이터 세션)에서 불렸으면** `2. Projects` 목록을 보여 주고 하나를 고르게 한다. 그다음 `bots_list` 로 그 폴더의 봇이 켜져 있는지 보고(없으면 `bot_start`), **`bot_send` 로 그 봇에 「/start」를 보내 거기서 돌리게 한다.** 오케스트레이터는 프로젝트 파일을 직접 고치지 않는다. 스폰이 안 되는 환경이면 이 세션에서 이어가되 그렇다고 말한다.
- `3. Area` 나 `4. Resources` 폴더에서 불려도 돌아간다. 다만 마감이 없으므로 6단계의 긴급도 축은 「상대가 답을 기다리는가」로 대신한다.

## 2단계 — 관문: 목적과 역할이 있는가

`CLAUDE.md` 를 읽고 `## 🎯 목적` 과 `## 🧑 나의 역할` 이 **문장으로** 있는지 본다.

| 상태 | 조치 |
|---|---|
| 둘 다 있다 | 통과. 목적 문장과 기한을 메모해 둔다 — 6단계의 저울이다 |
| 파일이 없거나 절이 비었다 | **`Skill(project-charter)` 를 먼저 실행**하고, 끝나면 3단계로 이어간다 |
| 폴더 자체가 비어 있다(readme 도 todo 도 없다) | 위와 같이 charter 를 먼저 하고, 4단계에서 바깥 사실을 모아 **readme.md 를 새로 만든다.** 이때는 폴더명의 날짜(=데드라인)와 타입 접두어가 유일한 단서이므로 그것부터 적는다 |

charter 를 돌리는 동안 사용자가 답해야 하므로 여기서 턴이 끊길 수 있다. 그래도 순서를 바꾸지 않는다. 목적 없이 만든 todo 는 다음에 또 「이게 왜 있지?」가 된다.

## 3단계 — 안쪽 읽기 (읽기 전용, 빠르게)

폴더 안에서 **「마지막으로 손댄 날」** 과 **「무엇이 진행 중이었나」** 두 가지를 뽑는다.

- 읽을 것: **`state.md`(지금 상태 — 있으면 여기부터)** · `CLAUDE.md`(목적·기한·역할) · `readme.md`(Overview · `## 🕐 최근 활동` · `## 🗒️ 히스토리`) · `todo.md`(미완료 · `## 확인 필요`) · `_agent/start-log.md`(지난 /start 기록, 있으면) · `vault_tree` 로 하위 폴더 이름만.
- 마지막 활동일은 폴더 안 파일의 가장 최근 수정 시각, readme 의 최근 활동 절, start-log 의 마지막 날짜 가운데 **가장 최근 것**으로 잡는다. 오늘과의 차이가 **공백 기간**이다.
- 공백 기간이 곧 4단계의 **조회 창**이다. 최소 7일, 최대 90일로 잡는다. 90일이 넘으면 「3개월 넘게 닫혀 있었다」고 브리핑 첫 줄에 적는다. 그것 자체가 정보다.
- 상대방 이름·기관명·프로그램명을 readme 와 CLAUDE.md 에서 뽑아 둔다. 4단계의 검색어다. **없으면 폴더명에서 뽑는다.**
- `vault_*` 도구가 없는 환경이면 `Glob`/`Grep` 과 파일 수정 시각으로 대신한다.

여기까지는 2~3분 안에 끝낸다. 폴더 안 문서를 통째로 읽지 않는다. 하위 폴더의 자료는 이름만 보고, 필요할 때 연다.

## 4단계 — 바깥 읽기 (병렬, 연결된 도구가 있을 때만)

**연결된 도구가 있으면 거기서 최근 변화를 가져오고, 없으면 폴더 안의 사실만으로 진행한다.** 이 세션에 연결된 채널(MCP 커넥터나 CLI)을 확인하고, 조회 창 안에서 **한 턴에 동시에** 연다. 채널별 절차는 [references/sources.md](references/sources.md) 에 있다. 각 채널을 열기 전에 그 절을 읽는다.

| 채널 | 무엇을 건지나 | 못 읽으면 |
|---|---|---|
| 📧 메일 | 상대가 보낸 요청·확정·변경·마감 | 「메일 측정 실패(이유)」 |
| 💬 메신저 | 결정이 가장 빨리 도는 채널. **이 프로젝트와 연결된 대화방만** 읽는다 | 「메신저 측정 실패(이유)」 |
| 📝 노트 앱 | 사용자가 **밖에서(모바일 등) 고친** 프로젝트 노트 | 다른 검색어로 다시 찾은 뒤에도 없으면 「노트 없음」 |
| 📅 캘린더 | 조회 창부터 기한까지의 일정. **폴더명 날짜와 다르면** 알린다 | 「캘린더 측정 실패」 |
| ✅ 할 일 앱 | 이 프로젝트로 이미 잡혀 있는 할 일 | 생략 가능 |

연결 자체가 없는 채널은 「측정 실패」가 아니라 「연결 안 됨」으로 한 번만 적고 넘어간다. 연결은 되어 있는데 조회가 실패했을 때가 「측정 실패」다.

건질 것은 **사실**이지 원문이 아니다. 채널마다 「날짜 · 누가 · 무엇이 바뀌었나 · 출처」 한 줄씩으로 줄인다. 대화 원문을 통째로 옮기지 않고, 개인 연락처·계좌번호는 옮기지 않는다.

채널끼리 어긋나면 **날짜가 최신인 쪽**을 채택하고 둘 다 남긴다. 근거가 없으면 `⚠️ 확인 필요` 를 붙인다.

## 5단계 — 한 번에 갱신

바깥 사실이 모였으면 **세 파일을 이 순서로** 쓴다. 승인은 필요 없다. 전부 되돌릴 수 있는 쓰기다.

**① `readme.md`** — 다섯 가지를 지킨다. 기계 구역(`## 📎 자료` · `## 🕐 최근 활동`)만 교체하고 나머지는 **덧붙이기만** 한다. 사용자가 쓴 문단은 한 글자도 덮지 않는다. 결과가 짧아지면 저장하지 않는다. 사실마다 출처를 쓴다. Overview 의 Status 줄이 바깥 사실과 어긋나면 **고치지 말고 바로 아래에 `> ⚠️ 확인 필요: …` 를 붙인다.** 파일이 없으면 새로 만든다(Overview · Timeline · 🕐 최근 활동 세 절이면 충분하다).

**② `todo.md`** — 이 파일은 사용자의 요청서다. 그래서 평소에는 에이전트가 새 항목을 임의로 넣지 않는다. 하지만 **`/start` 를 부른 것 자체가 「할 일을 정리해 달라」는 요청**이다. 그러니 넣되, 넣은 흔적을 남긴다.
- 바깥 사실로 **끝난 것이 확인된** 항목은 원문을 그대로 두고 `- [x] … → 처방: <근거>` 로 바꿔 `## 완료` 로 옮긴다. 요약으로 갈음하지 않는다.
- 바깥에서 **새로 생긴 할 일**은 `- [ ] <짧은 제목> — <상세> (제안 · 근거: 9/4 고객사 담당자 메일)` 형식으로 추가한다. `(제안 · 근거:)` 가 있어야 사용자가 자기 요청과 에이전트 제안을 구분한다.
- **남의 답을 기다리는 일**은 체크박스가 아니라 `## 확인 필요` 아래 일반 불릿 `- ` 으로 쓴다. 섞으면 「내가 할 일」과 「기다리는 일」이 한 더미가 된다.
- 파일이 없으면 만든다. 제목은 `# TODO — <프로젝트>` 로 한다. 항목은 평평하게 두고, 하나도 없으면 「지금 할 일 없음 — 근거」 한 줄을 쓴다.
- 제목 바로 아래 `> ▶ 시작 브리핑 …` 인용 블록은 **기계 구역**이다. 6단계 브리핑을 여기에 한 벌 더 남기고, 다음 /start 가 통째로 교체한다. 다음 세션이 채팅 기록 없이도 이어받게 하려는 것이다.
- 세션에 `vault-secretary` 팀원이 살아 있으면 직접 쓰지 말고 `SendMessage` 로 넘긴다. todo.md 는 그 팀원의 단독 소유다.

**③ `_agent/start-log.md`** — 에이전트 구역이라 자유롭게 쓴다. 맨 위에 오늘 한 줄을 덧붙인다: `- YYYY-MM-DD · 조회 창 N일 · 갱신: readme(2건)·todo(+1/✓2) · 측정 실패: 없음`. 다음 /start 가 「지난번 이후 달라진 것」을 계산하는 기준점이다.

**⛔ `CLAUDE.md` 는 쓰지 않는다.** (단 **`state.md` 는 갱신한다** — 브리핑 결과가 곧 현재 상태다.) 목적·기한·역할이 바깥 사실과 어긋나면(예: 상대가 마감을 미뤘다) 브리핑의 「결정이 필요한 것」에 올린다. 폴더명 변경도 마찬가지로 제안만 한다.

## 6단계 — 브리핑

형식과 예시는 [references/briefing.md](references/briefing.md) 가 정본이다. 쓰기 전에 읽는다. 핵심은 이렇다.

- **첫 줄은 「달라진 것」이다.** 지난 활동일 이후 무엇이 바뀌었는지 3줄 이내로 쓴다. 안 바뀌었으면 「변화 없음」 한 줄이면 된다. 그것도 답이다.
- **축은 한 문장이다.** 왜 지금 이것인지를 쓴다. 예: 「이번 주는 9/12 보고서 초안이 나머지 일정 전체를 연다」.
- **지금 당장 하나.** 소요 시간과 첫 5초 행동(열 파일, 연락할 사람, 칠 명령)을 붙인다. 시작 장벽이 진짜 병목이라 이 한 줄이 브리핑의 존재 이유다.
- **그다음은 최대 2덩이.** 한 화면에 3덩이 이하로 둔다. 항목이 더 많으면 자르지 말고 묶어서 이름을 붙인다.
- **결정이 필요한 것은 번호를 붙여 맨 뒤에 둔다.** 읽고 바로 답할 수 있게 선택지를 붙인다.

우선순위 저울은 둘이다. **긴급도**는 기한(폴더명·캘린더)과 「상대가 내 답을 기다리는가」이고, **중요도**는 CLAUDE.md 의 목적 문장을 얼마나 직접 앞당기는가다. 둘 다 높은 것이 「지금 당장 하나」다. 둘 다 낮은데 todo 에 있는 것은 브리핑에서 빼고 「목적 밖으로 보이는 항목」으로 결정 목록에 올린다.

## 7단계 — 끝내기

- `rondo_open` 으로 브리핑이 담긴 todo.md 를 띄운다. 「열어 보세요」라고 쓰지 않는다. 이 도구가 없는 환경이면 경로를 알려 준다.
- 사용자가 프로젝트와 대화방을 연결한 매핑표를 쓰고 있고, 이번에 처음 읽은 대화방이 있으면 그 표에 등록하고 마무리 보고에 한 줄 알린다.
- 「지금 당장 하나」를 할 일 앱의 오늘 일정에 올릴지는 **묻기만 한다.** 자동으로 만들지 않는다. 다른 동기화(예: `vault-secretary`)와 겹치면 이중 등록이 난다.
- 마무리 보고는 한 일 · 남은 일 · 필요한 결정 순으로 5줄 이내로 쓴다. 브리핑을 다시 반복하지 않는다.

## 이 스킬이 하지 않는 것

- 볼트 전체를 훑지 않는다. 그것은 `/weekly-review` 의 일이다.
- 파일을 지우거나 옮기거나 이름을 바꾸지 않는다. 정리할 것이 보이면 결정 목록에 올린다.
- 메일이나 메시지를 **보내지 않는다.** 회신이 필요하면 초안만 브리핑에 붙인다.
- 메신저 전체를 키워드로 훑지 않는다. 대화방을 먼저 특정한다. 방을 가리지 않고 키워드로 훑으면 개인 대화가 섞인다.
