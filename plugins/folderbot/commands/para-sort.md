description: 1. Inbox의 미분류 항목을 PARA 원칙에 따라 분류·이동 제안
---
인박스의 모든 항목을 살펴보고 볼트의 폴더 규칙에 따라 정리안을 만들어라.

**폴더 역할은 볼트 루트 `CLAUDE.md` 의 「폴더 규칙」 절에 있는 ```` ```yaml folder-rules ```` 블록에서 읽는다.** 이 블록의 `roles`(inbox·active·reference·archive)가 어느 폴더가 무슨 역할인지 정하고, `naming.project` 가 새 프로젝트 폴더 이름을 정한다. 블록이 없으면 `preset: para` 기본값을 쓴다. 아래 폴더 이름은 그 PARA 기본값 기준이다. 볼트가 다른 프리셋을 쓰면 블록에 적힌 폴더로 바꿔 읽는다.

분류 기준 (볼트 `CLAUDE.md` 에 적힌 원칙이 먼저다):
- **Projects** (active) — 마감이나 목표가 있는 진행 중 작업 → `2. Projects/YYYY[-MM[-DD]]_[타입-]이름`. 날짜는 시작일이 아니라 **데드라인**이고, 타입은 강의·컨설팅·코칭·모임·행사·집필처럼 일의 종류를 쓴다. `naming.project` 가 따로 있으면 그 패턴을 따른다.
- **Area** (active) — 상시 운영하는 영역과 자주 꺼내 보는 레퍼런스 → `3. Area`
- **Resources** (reference) — 관심사와 관련 자료. 「언젠가 쓸 자료」 창고가 아니다 → `4. Resources`
- **Archive** (archive) — 수명이 다한 것. 여기에 새로 만들지 않고 **옮기기만** 한다 → `5. Archive`

절차:
0. **`jev-judge` 스킬이 설정돼 있으면 먼저 1차 분류를 맡긴다** — `jev inbox` (PATH 에 없으면 jev-judge 스킬 폴더의 `scripts/jev inbox` — `scripts/setup.sh` 를 한 번 돌리면 `jev` 로 부를 수 있다). 결과의 `band` 에 따라 다르게 쓴다.
   - `dup`(볼트에 같은 파일이 이미 있음)·`suggest`(신뢰도 0.9 이상)는 그 결과를 출발점으로 삼되, 한 번 훑어 이상하면 뒤집는다.
   - `pick2` 는 후보 둘을 그대로 제안에 올린다.
   - `llm`(모름·민감어·오류·비용 가드)은 결과를 버리고 1번대로 직접 연다.
   - 스킬이 없거나, 종료 코드 3 이나 경고를 내면 그 사실을 사용자에게 알리고 **1번부터 직접 판단한다.**
1. 각 항목을 열어 성격을 판단하고, 항목마다 `현재 위치 → 제안 위치 (근거 한 줄)` 표로 정리한다.
2. 애매한 항목은 후보 두 곳과 판단에 필요한 질문을 함께 낸다.
3. **사용자가 승인한 것만** 실제로 옮기고, 옮긴 결과를 요약한다. 10개 이상을 한꺼번에 옮길 때는 실행 직전에 한 번 더 묻는다.
4. 중복으로 보이는 항목은 이름이 아니라 **해시(`shasum -a 256`)가 같을 때만** 중복으로 판정한다. 지우는 대신 휴지통으로 보내고, 사본이 하나 이상 남는지 먼저 확인한다.
